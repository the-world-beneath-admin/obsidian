# World Keys Kickstarter And Itch.io Readiness Plan

## Status

Active plan - created 2026-05-11.

## Purpose

Prepare the first two World Keys for free public release on itch.io, then use those playable releases as proof for the Kickstarter and broader marketing funnel.

## Platform Split

Itch.io is the first playable release channel.

Kickstarter is the campaign, funding, update, and community-conversion layer.

The website is the owned hub that ties both together.

The landing page should point visitors toward playing the first free World Keys while they wait for the full game. The book and audiobook are deeper story/lore paths, not the primary play-now conversion.

## Core Rule

The first two World Keys should be free, playable proof. They should not accidentally become a second main game, a confusing demo label, or a Kickstarter reward that contradicts the public free-release promise.

## Confirmed First Two World Keys

1. The Garden
2. The Alchemy Lab

The Garden is the public title for the garden/farming World Key. Glassroot Garden is now an internal or historical prototype label, not the public name. Players name their own garden when they first open it.

The Alchemy Lab is the public title for the second World Key. Players name their own lab when they first open it.

## Step-By-Step Plan

1. Choose the first two World Keys

   Complete. The first two releases are The Garden and The Alchemy Lab.

2. Write a one-page release brief for each World Key

   Complete. Draft page-copy briefs are in [[world-keys-itch-io-release-briefs]].

   Each brief should include:

   - Title
   - One-sentence hook
   - Player fantasy
   - Core loop
   - Controls
   - Estimated play length
   - Win or completion condition
   - Connection to The World Beneath
   - What is deliberately not included

3. Define the shared World Key promise

   Explain how free World Keys relate to the main game:

   - Are they standalone?
   - Are they side stories?
   - Do they unlock anything later?
   - Do they teach mechanics?
   - Are they proof-of-world entries?

   If account sync or later import is not ready, say so plainly.

4. Prepare itch.io build requirements

   If the keys are browser-playable HTML5 games, each upload should be a ZIP containing an `index.html` entry point and relative asset paths. Test case-sensitive file references before upload.

5. Prepare itch.io pages

   Each World Key page needs:

   - Cover image
   - Title
   - Short description
   - Long description
   - Screenshots or GIFs
   - Controls
   - Accessibility notes
   - Tags
   - Browser/play/download instructions
   - Known issues
   - Link back to the World Keys hub on the website

6. Set itch.io pricing correctly

   Use free release settings for the first two World Keys. If accepting optional support, keep the language clear that the first two are free to play. If no payments are desired, disable payments rather than creating a confusing donation prompt.

7. Check itch.io indexing readiness

   Itch.io indexing requires the project to be public, have a cover image, and be downloadable, purchasable, or playable in browser. Tags and metadata should be accurate; tag abuse can damage visibility.

8. Publish the first itch.io World Key privately or unlisted for QA

   Use a small tester pass before public release:

   - Desktop browser
   - Mobile browser only if claiming mobile support
   - Audio start behavior
   - Save/reset behavior
   - Fullscreen behavior
   - Load time
   - Broken asset checks

9. Launch the first two World Keys publicly on itch.io

   Publish only when both the game page and playable build are credible. Announce through:

   - Website World Keys page
   - Website blog/devlog
   - Email/register list
   - Social posts
   - Itch.io devlog

10. Create the Kickstarter campaign foundation

   Kickstarter should be built around the main project and supported by the free World Keys. Prepare:

   - Campaign title and subtitle
   - Hero image
   - Campaign video
   - Project story
   - Funding goal
   - Budget explanation
   - Timeline
   - Risks and challenges
   - Playable proof section linking to itch.io

11. Build Kickstarter rewards carefully

   Rewards should not paywall the first two free World Keys. Use rewards that are deliverable and do not conflict with the free release promise:

   - Digital art pack
   - Soundtrack or music sampler
   - Backer name in credits
   - Backer-only development updates
   - Cosmetic name submissions, only if moderation is planned
   - Beta access to later builds, only if schedule is credible
   - Physical rewards only if fulfillment cost is known

12. Create the Kickstarter pre-launch page

   Kickstarter pre-launch can collect followers and notify them at launch. Set it up only after the campaign image, title, subtitle, creator profile, and public call-to-action are ready.

13. Run a pre-launch proof period

   Before launching the campaign, measure whether the free World Keys are actually helping:

   - Itch.io plays/downloads
   - Website clicks to itch.io
   - Email signups
   - Kickstarter pre-launch followers
   - Comments and confusion points
   - Most repeated player questions

14. Launch Kickstarter only after the proof is clean

   The campaign should launch when:

   - The first two World Keys are public and stable.
   - The campaign page has been reviewed.
   - Rewards and fulfillment dates are realistic.
   - The website points to Kickstarter cleanly.
   - The team can publish campaign updates during the live window.

## Itch.io Ready When

- The first two World Keys are named.
- Each key has a release brief.
- Each build runs from its packaged upload.
- Each page has cover art, screenshots, tags, description, controls, and known issues.
- The pages clearly say the first two World Keys are free.
- The website has a clear route to the itch.io pages.
- No account-sync, unlock, or main-game import claim is made unless it is working.

## Kickstarter Ready When

- The campaign explains the main project, not just the free World Keys.
- The first two World Keys are live as playable proof.
- The funding goal is tied to a credible development budget.
- Rewards are deliverable.
- The pre-launch page has a clear "notify me" call-to-action.
- Campaign video, page story, risks, FAQ, and update cadence are ready.
- Kickstarter traffic has somewhere useful to go before and after the campaign.

## Not Ready If

- The first two World Keys are unnamed.
- The builds only work locally.
- Itch.io pages are placeholder pages with no real cover art or screenshots.
- Kickstarter rewards depend on features not yet scoped.
- The campaign suggests the first two free keys are exclusive paid rewards.
- The website cannot clearly explain the relationship between World Keys and the main game.
