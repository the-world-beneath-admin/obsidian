# Steam Coming Soon Readiness Plan

## Status

Active plan - created 2026-05-11.

## Purpose

Prepare The World Beneath main-game Steam Coming Soon page as the wishlist and public store funnel.

This plan is for the parent game, not for individual World Keys. The first free World Keys can support the funnel as proof-of-play, but they should not replace the Steam page's main-game promise.

## Platform Guidance Checked

- Steamworks Coming Soon documentation: https://partner.steamgames.com/doc/store/coming_soon?l=english
- Steamworks store page documentation: https://partner.steamgames.com/doc/store/page?l=english
- Steamworks graphical assets documentation: https://partner.steamgames.com/doc/store/assets?l=english
- Steamworks graphical asset rules: https://partner.steamgames.com/doc/store/assets/rules

## Core Rule

The Steam page should not go public until the page can clearly answer:

- What is the core loop?
- What can the player actually expect at launch or early access?
- What is only future ambition?
- What should the player wishlist?

## Step-By-Step Plan

1. Confirm the Steam product scope

   Define the Steam page as The World Beneath main game. Do not make Glassroot Garden or another World Key sound like the whole product.

2. Lock the approved positioning foundation

   Use the approved pitch:

   `Run dungeons. Grow creatures. Shape the world beneath.`

   Support it with the approved frame:

   `The World Beneath is a shared-world RPG where dungeon runs feed creature growth, crafting, inventory progression, and a larger hidden world shaped by player societies.`

3. Define the public feature boundary

   Split store claims into:

   - Live or confidently deliverable
   - In development
   - Roadmap or future ambition
   - Not for the first Steam page

4. Draft the Steam copy pack

   Prepare:

   - Short description
   - Long description
   - Feature bullets
   - About-this-game section
   - Early access statement if needed
   - System requirements draft
   - Developer and publisher text

5. Prepare the visual asset list

   Steam requires store and library graphical assets. Current required assets include capsules, screenshots, library assets, app icons, and related artwork. Use the current Steam templates before production because Steam asset sizes and rules can change.

6. Create honest screenshot and trailer criteria

   Screenshots should show actual gameplay, not concept-only promises. Trailer footage should make the loop readable:

   - Dungeon run
   - Creature growth
   - Inventory or crafting payoff
   - World or society layer, only if it is safe to show

7. Pick initial Steam tags and categories

   Start from the current tag hypotheses:

   - RPG
   - Dungeon Crawler
   - Creature Collector
   - Party-Based RPG
   - Crafting
   - Loot
   - Inventory Management
   - Fantasy
   - Strategy RPG
   - Resource Management

   Validate these before publishing.

8. Build the wishlist funnel

   Connect:

   - Website homepage
   - World Keys page
   - Press page
   - Email/register funnel
   - Itch.io World Key pages
   - Kickstarter pre-launch page, if active

   Do not send users to a Steam Coming Soon page until it looks credible enough to convert.

9. Complete Steamworks commercial and admin setup

   Confirm:

   - Steamworks account access
   - App created
   - Tax/payment/admin information
   - Product landing checklist
   - Package/pricing/release-date settings

10. Submit for Valve review

   Steam documentation says the product must complete the store presence checklist and be reviewed before posting publicly as Coming Soon. Submit the page at least 7 business days before the intended public page date.

11. Post as Coming Soon

   After approval, publish the page and start using it as the central wishlist destination.

12. Monitor and update after launch

   Track:

   - Wishlist growth
   - Store page click-through from website
   - Trailer retention if available
   - Community questions
   - Confusing claims
   - Tags that attract the wrong audience

## Ready When

- Main-game scope is unambiguous.
- Short and long descriptions are approved.
- Capsule/key art is produced from current Steam templates.
- Gameplay screenshots exist and match the actual build.
- Trailer footage shows the real loop.
- Tags are reviewed against competitor and player expectations.
- Release window is chosen conservatively.
- Website and itch.io pages point to the Steam page only after it is public.
- Claims about societies, trade, territory pressure, account sync, and World Keys are accurate.

## Not Ready If

- The page reads like Glassroot Garden is the main game.
- The page promises systems not supported by the current build or reliable roadmap.
- The visual assets are placeholder art.
- The screenshot set hides the actual gameplay loop.
- The short description is lore-heavy but gameplay-light.
- The page exists only because "we should have Steam" rather than because it can convert wishlists.

## Memory Labels

- Decision - Steam Coming Soon is the main-game wishlist funnel.
- Warning - Do not publish a Steam page until the core loop, visuals, and public feature boundary are clear.
- Open Question - Should the first public Steam page use "Coming Soon" only, or "Early Access" language?
- Open Question - Which Steam tags convert best for a dungeon-running, creature-growth, shared-world RPG?
